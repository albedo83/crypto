## Suite technique

Incident de mesure lors du premier run : le harnais changeait
`BACKTEST_SLIPPAGE_BPS` sans mettre à jour `COST`, alias calculé à l'import dans
le moteur historique. Les sorties identiques à 4/6 bps ont révélé le défaut.
Premier run conservé dans `macro_recheck_2026_09_17_invalid_cost_alias.json`,
invalide pour le verdict global. Correction du harnais (aucune règle modifiée),
coût effectif désormais affirmé et publié, puis répétition de la même grille.

La référence attachée aux entrées réelles de Live doit séparer :
1. résultat local d'une intervention sur la même position ;
2. effets ultérieurs des slots, cooldowns et tailles sur le portefeuille.
Un simple changement de taille contrefactuel ne mesure pas le point 2.
Ne pas publier une économie causale totale avant un rejeu de portefeuille complet.

Le changement de prompt est une nouvelle expérience, identifiée par ses hashes.
Les modes d'action restent ceux de production ; leur lecture doit être vérifiée
au déploiement sans exposer les secrets. Aucun réarmement IA implicite.
